# Architecture

LEGAL MASTER uses a modular monolith to keep local development simple while preserving explicit boundaries.

```text
React UI -> FastAPI API -> application modules -> PostgreSQL
                                     |         -> private document storage
                                     |         -> Redis (future jobs)
                                     |         -> Qdrant (future vectors)
                                     `---------> provider interfaces (future AI)
```

## Boundary rules

- API routers validate transport data and delegate work; they do not perform storage or database operations directly.
- Services will coordinate use cases, repositories will own SQLAlchemy queries, and models will remain persistence-focused.
- Every workspace-scoped query must include workspace authorization. Vector payloads will carry workspace, case, document, version, and page identifiers so retrieval can enforce the same boundary.
- Storage keys are generated by the application. Original filenames are metadata only and must never become filesystem paths.
- AI, extraction, OCR, chunking, storage, and vector integrations depend on internal interfaces. Provider-specific clients stay at the boundary.
- Background processing remains part of the same codebase and transaction model; Redis-backed workers can be added when ingestion arrives.

### Authentication boundary

Phase 2 authentication uses Argon2id password hashes and two JWT types. Short-lived access tokens are stateless bearer credentials. Refresh tokens are rotated on every use; their `jti` values are stored in PostgreSQL so logout, expiration, and reuse can be enforced without storing raw token material. Browser refresh tokens use an HttpOnly cookie while access tokens remain in memory.

## Current runtime

The API exposes `/health`, `/api/v1`, and registration, login, refresh, logout, and current-user operations under `/api/v1/auth`. PostgreSQL contains the `users` and revocable `refresh_tokens` session tables. Other domain routers remain composition points only; no Phase 3 or later feature is implemented.
